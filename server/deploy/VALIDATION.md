# 公网安全层源码交付与验证（2026-09-22）

## 结论

代码、配置模板、标准接入说明、独立Python客户端、邀请/数据库工具和自动测试已交付。没有部署云服务、修改真实网络/防火墙或账号库、启动原客户端/VM、推送GitHub。玩法features和client_verified未改变。

**不能宣称全部公网验收完成。** 100账号的延迟、资源和清理指标通过，但UDP接收量与预期转发量有约4%的差额；额外的99%回环送达质量门未通过，报告中的`capacity_accepted`仍为false。

## 实现范围

- 独立public入口，显式TLS/数据库版本/安全策略；旧实验入口不自动变成公网服务。
- 邀请码摘要、单次事务兑换、真实scrypt、有界2执行+8等待、公平限流、会话撤销与连接租约。
- TLS前连接预算、首包/准入/半包期限、账号与全局队列预算、有限错误指标和轮转日志。
- 复用现有解析器/handlers/Store，默认拒绝未开放消息、检查身份/房间/归属/明确字段；未知业务不伪造成功。
- 服务端禁用客户端战斗结果的永久收益，即使旧库存在任务/奖励规则也不例外。
- 显式迁移、一致性backup API、恢复到新路径、只限本人读取的资产审计；不声称原购买协议有跨重连恰好一次保证。
- 可选原客户端工具去除固定实验目录和防火墙前置要求；服务接入不依赖该工具、PID或VM。

## 压测中纠正的问题

1. 准入100人但RoomHub仍限制全局8人：已修正，单房8人限制保留。
2. Windows异步UDP发送队列堆积至64 MiB并丢弃：已确认并修正。公网发送使用同一已绑定UDP端点的独立非阻塞句柄，不增加代理或协议层；内核繁忙只丢当前数据报并计数，不复用nonce重传。修正后队列峰值为0。
3. 初版管理工具绕过仓储边界：已移入专门的schema/maintenance模块，未放松业务层禁止直接SQL的检查。
4. 有效MAC不等于UDP源端口可达：已加原生随机session回显门。该门与后续配置别名保护通过定向回归；不把较早启动的30分钟进程误称为覆盖了所有随后提交的完整版本。

初次30分钟基线和短测失败结果均保留，未覆盖或重写。剩余约4%差额不能仅凭现有计数全部归因于某一层，可能涉及负载生成调度、内核接收或阶段边界；需要独立环境进一步定位，不靠扩大缓存或放松认证限流消除告警。
