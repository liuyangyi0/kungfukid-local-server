# 公网非排位测试部署模板

模板只交付文本，不自动创建用户、安装服务、改安全组或修改现有网站。
Python 3.12及固定依赖见仓库requirements；保留单进程SQLite写入，不开启多worker。

## 上线前配置

1. 创建专用非root用户`kk-game`。源码放`/opt/kk-server`，由管理员拥有且服务只读；状态和日志分别放`/var/lib/kk-server`、`/var/log/kk-server`，仅服务用户可写。
2. 从`server/configs/public.example.json`复制`/etc/kk-server/public.json`，改成绝对路径。策略文件单独放`/etc/kk-server/public-policy.json`。显式配置listen_host、advertised_host、TLS证书和私钥。示例回环地址不代表已公开服务。
3. 私钥不可放源码/网页根目录/账号库；最小读取权限给服务用户，目录不可被服务改写。使用有效证书及正确DNS名称。认证客户端必须验证证书，不安装“接受所有证书”回调。
4. 新库用`public_admin init`；旧库停服后`migrate --backup 新文件`。不要让服务自动升级未知库。使用系统文件权限保护DB、WAL、SHM、锁文件和备份。
5. 仅开放认证TLS、SDK身份TCP、游戏TCP、游戏UDP的实际配置端口。健康端口固定回环，数据库、SSH管理、备份不得作为游戏API开放。SSH只对管理员来源开放；本计划不执行安全组变更。
6. 在对应部署发行版检查systemd模板支持的沙箱选项，然后再由管理员启用。`MemoryMax=2G`和`CPUQuota=200%`是进程预算，不是带宽保证。模板不会改其他网站服务。

## 运维

- `GET http://127.0.0.1:18090/healthz`与`/readyz`只说明进程/监听就绪；`/metrics`为固定标签的JSON指标，不是安全认证。
- JSON运行日志每10秒汇总，10 MiB轮转保留5份。持续观察CPU、RSS、event-loop p99、UDP发送队列、拒绝原因、资产库大小和磁盘剩余量。
- SDK/游戏断开按有限错误类型累计；启动握手只计固定编号及方向，不保存正文或凭据。`native_handshake_tx_1151`表示已交给发送器，不表示原客户端已处理；`native_game_login`也不等于已进入大厅。准备中的已认证引导连接受原授权截止约束，不能靠心跳持续占用；未采用延长一般资料加载超时的试验方案。
- 临时玩家全部删除、重置库存、注入全武器/测试余额等旧工具不要用于公网库。正式模式不接受这些网络操作；本地管理员仍具备修改数据库的能力，应独立审计。
- 邀请码只通过本地管理员工具生成/撤销。维护工具与服务使用同一个DB租约；需先停止服务。密码/邀请码使用隐藏输入，不放命令行。账号封停/密码修改持久化后，下次启动授权重新建立；运行中的内部撤销事件立即清理关联授权。
- 备份用SQLite backup API；恢复仅写新路径。备份保留政策由运营制定，至少保留迁移前副本与最近可恢复版本，并进行余额、物品数量、业务收据及完整性对账。不要自动删掉幂等收据来“清理日志”。
- 磁盘不足、外部写锁、密钥/证书失效必须停止接收新业务并处理告警；本实现数据库锁不等待，失败交易回滚，不无限阻塞事件循环。
- 防护超出链路容量时需要云厂商清洗/上游ACL。100人带宽以本地压力报告的实际Mbps与部署网络为准，另留协议/IP头和突发余量。不承诺任意DDoS下可用。

## 回退

停服务，保留当前库和日志，选取已验证源码版本及匹配schema的备份恢复到新路径，核对后修改配置。禁止将新版本库直接交给旧版本写入，不覆盖唯一备份，不声称提交回退等于数据回退。

## 验证入口

`python -m server.tools.public_benchmark --output 全新目录 --players 100 --seconds 1800 --attack-seconds 60`

只创建合成账号和临时证书，只访问回环。报告包含约束是否实际生效、延迟直方图、CPU/RSS、队列、收发与清理。使用真实scrypt/AES-GCM。Windows job/affinity或Linux affinity/RLIMIT是进程预算检查；Linux systemd模板本身需在目标发行版另行验证。没有权限限制资源时报告未验证，不能把100个连接当100人容量合格。

下一步只能另行安排部署环境受控试运行；本工具不自动部署或购买云防护。
