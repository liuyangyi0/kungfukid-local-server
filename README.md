# KungFuKid Local Server

**《功夫小子》自建兼容服务端、独立登录器与客户端接入工具。**

本项目面向持有合法客户端副本的开发者和测试玩家：使用自己的账号服务完成注册、登录与选区，在自建服务器上进入大厅、创建房间和进行多人对战。

- **Python 服务端**：账号、角色、背包、商城、大厅、房间与对战中继。
- **C# 登录器**：独立 EXE，提供注册、登录、区服选择和服务器地址设置。
- **C++ 接入适配**：让已适配的原客户端使用自建认证与加密通道，保留原游戏业务消息。

这是开发中的兼容服务项目，不是官方服务端源码，也不是完整游戏安装包。仓库不包含原游戏、游戏素材、账号数据库或认证私钥。当前面向**非排位测试**，不宣称已经恢复全部协议、支持所有客户端版本或具备完整反作弊能力。

## 目前能做什么

| 模块 | 已有能力 | 使用边界 |
|---|---|---|
| 账号与登录 | 邀请码注册、密码验证、会话、区服选择、一次性接入授权 | 不使用旧运营账号；账号属于实际连接的自建服务器 |
| 登录器 | 注册/登录、修改 IP 与端口、证书名称设置、启动游戏、交接凭据、登录失败提示 | Windows x64 / .NET Framework 4.8；游戏与适配组件需要自行准备 |
| 角色与装备 | 角色资料、背包、已支持槽位的装备与道具处理 | 特殊物品和未覆盖操作仍需单独适配 |
| 商城与资产 | 配置驱动的商品目录、购买及部分赠送、修理、续费、升级业务 | 价格与资格由服务端决定；不提供真实充值 |
| 大厅与房间 | 建房、列表、加入、退出、准备、换队、房主及开局流程 | 单房最多 8 名参战者，并受地图容量约束 |
| 对战网络 | 同房 TCP/UDP 中继、已准入的动作/命中/防御及部分状态消息、结束流程 | 不是完整服务端权威战斗；不是所有技能和特殊模式都已支持 |
| 存储与运维 | SQLite 持久化、事务、迁移、备份、健康检查、限流与资源预算 | 单进程写入；需按部署环境配置证书、权限与容量 |

部分邮件、任务、修炼与奖励业务也有实现，但各自有适用范围。**存在解码器不等于业务已完成，也不等于公网模式已启用。** 当前规则和限制以[服务规范](docs/SERVICE.md)与运行配置为准。

客户端上报的胜负、HP 与击杀不能作为可信奖励依据：公网非排位模式不会据此发放永久金币、经验、任务进度、排名或物品。

## 支持的客户端版本

当前参考游戏构建为 **`Version.dat → [Common] Version=1.13.0.594`，32 位 i686 客户端**。

这只是构建标识，不是“所有同版本安装包均兼容”的保证。主程序、资源与登录组件组合也必须匹配。

| 入口/组件 | 当前范围 |
|---|---|
| 独立 C# 登录器 + 加密适配 | 面向项目已适配的上述参考客户端；初始化器、SDLogin/SDP2P 等模块另有身份与接口检查 |
| 原 SDO 登录窗口兼容代码 | 参考组合使用 `SdoBaseClient.dll 2.2.2.0` 及匹配的 `sdologin.exe / duilib.dll` |
| `SdoBaseClient.dll 2.3.3.0` | 尚未适配或验证；不能只改检查常量绕过拒绝 |
| 其他游戏构建或混合组件 | 未验证；请先提交非敏感版本信息，不直接替换 DLL |

详细组件身份、只读检查方法和新版本适配要求见[客户端兼容说明](docs/CLIENT_COMPATIBILITY.md#sdk-build-compatibility)。

仓库没有可推荐的、已核实授权与完整性的客户端公开下载地址，也不分发原客户端。**把原 EXE 改名为 `gfxz-lab.exe` 不等于完成适配。**

## 系统结构

```text
独立登录器 ── TLS ──────────> 账号 / 区服 / 授权服务
    │
    └─ 启动游戏、在内存中交接凭据
           │
      已适配客户端 ── 加密 TCP ──> 大厅 / 房间 / 资产 ──> SQLite
                   └─ 加密 UDP ──> 同房对战中继
```

登录器不代理游戏流量；适配模块在原套接字上处理加密记录。服务端依据账号、授权与房间状态进行校验，不把客户端程序、进程身份或客户端环境当作可信证明。

第三方可以按[公开接入规范](docs/SERVICE.md)实现自己的客户端，不要求使用本项目登录器。兼容规则与自建设计有所区分，后者不能视为恢复了旧运营服务端实现。

## 快速开始

### 1. 获取源码与验证

需要 Python 3.12。以下命令从仓库根目录执行：

```shell
git clone https://github.com/liuyangyi0/kungfukid-local-server.git
cd kungfukid-local-server
python -m pip install -r requirements.txt
python -m unittest discover -s server/tests -p "test_*.py" -v
```

这些测试使用临时数据库和合成数据，不要求安装游戏，也不应指向正在使用的账号库。

### 2. 配置服务端

从 [public.example.json](server/configs/public.example.json) 与 [public-policy.example.json](server/configs/public-policy.example.json) 创建自己的配置，填写数据库、日志、TLS 证书、私钥、监听地址与对外地址。

- 示例默认监听回环；开放服务前必须显式配置。
- 新库先初始化；旧库先停服、一致性备份，再执行迁移。
- 邀请码通过管理员本地工具生成，不能使用测试夹具里的账号或凭据。
- 不要通过改监听地址把免认证实验模式当作公网模式。

```shell
python -m server.kk_local --settings /etc/kk-server/public.json --check-config
python -m server.kk_local --settings /etc/kk-server/public.json
```

完整步骤见[部署指南](docs/DEPLOYMENT_WALKTHROUGH.md)与[服务运维说明](server/deploy/README.md)。源码包含非 root systemd 模板，不会自动修改已有网站或云安全组。

### 3. 安装登录器并进入游戏

玩家的使用流程：

**打开“功夫小子启动器.exe” → 服务器设置 → 注册或登录 → 选择区服 → 进入游戏。**

编译登录器：

```powershell
powershell -NoProfile -File tools/client-lab/Build-KkLauncher.ps1 -OutputDirectory build/launcher
```

仅有 EXE 还不够：还需兼容客户端、配套适配 DLL、注入器、初始化器与安装配置。三个工具均提供自有源码及[构建与安装说明](tools/client-lab/native-cloud-ticket/README.md#先构建三个接入工具)，其中 `Build-KkClientInitializer.ps1` 生成 `kk1-official-flow.dll` 和 `kk_inject.exe`；初始化日志运行时自动生成。不要单独拷贝 EXE 后期待自动完成客户端适配。

“服务器设置”中的证书名称是证书对应的域名或 IP，**不是证书文件路径**。公开证书的加载路径由安装配置指定；不会自动信任陌生服务器提供的证书。密码错误有独立提示，密码和授权凭据不会保存到地址设置中。

## 当前限制与安全边界

- 协议和特殊玩法仍在补齐；暂不承诺完整战斗重连、所有模式或所有装备行为。
- 对战以客户端兼容与中继为主，尚非完整权威模拟。加密可以防篡改与重放，不能阻止合法账号提交作弊请求。
- 公网目标是 100 名在线账号，不等于任何机器都能稳定承载 100 人。已有压力报告仍有收发差额待闭合，详见[容量与验证报告](server/deploy/VALIDATION.md)。
- 限流、队列与权限校验用于限制服务资源消耗，不承诺抵御任意规模的链路级攻击，也不替代独立安全审计。

截至 2026-09-23，最近一次干净源码回归通过 763 项服务测试、19 项客户端兼容工具测试和 8 项资源工具测试；登录器及加密适配另有模型测试。这是对应代码的验证结果，不代表所有原客户端功能已经验收。
