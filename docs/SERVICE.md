## 公网标准接入 v1（2026-09-22）

本节是自建服务的 **SYSTEM_DESIGN_INFERRED / PROVISIONAL** 接入合同，不是旧运营服实现。旧章节中的 PID、就绪文件、免认证夹具与 VM 要求不适用于 `--mode public`。公网模式默认仍监听回环；显式配置监听、对外 IPv4、TLS 与安全策略后才允许其他机器连接。服务不要求指定 DLL、Windows 或 VM。

### 认证与连接顺序

认证端口使用 TLS 1.2+，必须验证证书链和主机名；每次连接只处理一个请求。帧为 **4字节大端长度 + UTF-8 JSON**，请求最多8192字节，响应最多65536字节。禁止重复 JSON 字段、NaN/Inf 和超过16层嵌套。

```json
{"schema":"kk-local-auth-v1","operation":"capabilities","arguments":{}}
```

成功回复 `{"ok":true,"result":...}`，业务失败回复 `{"ok":false,"error":"稳定错误码"}`。畸形帧、超时、TLS失败可能直接关闭连接。客户端不得把连接关闭解释为业务成功。

按顺序调用：

1. 新账号：`register(account,password,invite_code,nickname?)`。邀请码必填、默认7天单次有效，旧账号不重新注册。密码12–128个Unicode字符，UTF-8最多512字节；账号3–20位ASCII字母/数字。只在TLS内传输。
2. `login(account,password)` → `uid/session/expires_at`。会话8小时；不存在账号与错误密码同为 `invalid_credentials`。限流或繁忙不是密码错误，不撤销已建立会话。
3. `regions(session)` → 可用区域；`select_region(session,region_id)` → 45秒单次票据。
4. `authorize_game(ticket,region_id)` → 独立 `game_credential/udp_credential/sdk_credential`、`transport_id/transport_key`、SDK/游戏/UDP端点与过期时间。票据只能消费一次，同账号重复准入返回 `account_already_online`，不能踢掉原连接。授权响应不得持久化到普通日志。
5. SDK身份初始化通道：建立加密TCP；先发 `KKS1 + 32字节sdk_credential原始值`，再沿用登录帧 `flags=1, id=1001`；消费1002回复，发送1011取目录、接收1012。历史名称“SDK”只表示协议角色，不要求旧SDK程序。
6. `client_ready(session,game_credential)` 表示客户端能接收资料，**不是鉴权或反作弊证明**。
7. 游戏引导连接：在加密TCP上发送96字节1010，UID与已认证账户一致，`+17..48`放32字节游戏凭据、`+49`为build594、`+73`为账号；等待1151资料，发送3320选择1，消费1201换线；关闭引导连接。
8. 新游戏TCP连接发送同形2010，消费2030，发送2250选择目录。实例不会接受客户端自行指定别人的UID。
9. UDP同样加密；1001原登录用户数据字段携带 `KKN1:` 加64字符小写十六进制UDP凭据，剩余补零。消费1002生成的peer/session，先用正常1013心跳回显服务随机session并接收1014，再在游戏TCP发送1156绑定UID与peer。收到回显前，该端点不能成为房间放大转发目标；只有有效MAC但不能接收该端点回复仍不够。端点来自实际套接字，不是任意请求地址；变更端点需重新授权。
10. 定期发空TCP消息0、UDP1013保活；SDK通道保留至退出。允许每授权最多4个已认证TCP连接。用3010创建或3070加入房间，沿用4030/4160/8040准备屏障；收到8070后进入战斗。
11. 返回选区2060、重新2010仍受当前授权与换线期限约束。注销用 `logout(session)`；撤销立即使关联授权失效。服务重启后所有内存中的游戏授权失效，重新登录并取新授权，不能重用旧密钥/序号。

查询 `entry_status(session,uid)` 只允许本人。取消尚未完成的入场用 `cancel_game(session,game_credential)`。无PID API、无免认证入口、无就绪文件授权、无明文降级。

### 加密记录与重放

`kk-aesgcm-v1` 保持原格式；不新增游戏业务封装。固定头使用网络序 `!4sBBH16s16sQI`：

- magic=`KKE1`，channel=1 SDK / 2游戏 / 3 UDP；direction=0客户端发 / 1服务端发；reserved=0；
- sid为授权的16字节transport_id；TCP cid为每条新连接独立随机16字节，UDP cid全零；
- seq为64位序号，从0递增；本实现单方向上限2^32条，达到上限重新授权；
- size为明文长度1..32768；头后为密文与16字节GCM tag，头部整体作为AAD。

每个通道、方向、连接独立派生AES-256-GCM密钥：HMAC-SHA256(master, `KK-native-record-v1\0` + 单字节channel + 单字节direction + sid + cid)。nonce为4字节零 + 8字节大端seq。master为认证服务随机生成的32字节密钥，经TLS下发。TCP严格连续序号；UDP允许1024条乱序窗口，认证成功才推进窗口。篡改、错误密钥、重放、旧授权均不得交给业务解析器。TCP cid在同授权下禁止复用。

此记录层没有独立于TLS的应用层前向保密握手，未声称通过第三方密码协议审计。具体字节实现与固定向量以 `native_crypto.py` 及相关测试为准；224字节配置只属于可选Windows适配器，不是服务端要求。

### 消息权限与开放范围

长度/阶段入口在 `public_commands.py`，字段含义、失败回复、归属和原子操作仍复用既有handlers与Store，不维护第二套业务实现。所有业务以连接中的账号身份为准。

- 全局100账号、100房；每房最多8参战者，还受地图容量限制。
- 初期开放Mode0/1/2/3/5的已支持房间流程、基本战斗中继、装备、已审计的商城/赠送/邮件附件/修理/续费/升级路径。目录/报价必须在数据库中事先明确配置；不会自动填充测试商品或余额。
- 公网UDP只接受完整、可解析的8071帧，每个数据报1–8帧、最多7个同房目标。基本子消息为8120/8121/8122/8125/8127/8143/8280/8284/8287/8293。状态机要求当前参战身份、发送者与目标归属成立；已携带局编号的消息必须匹配当前局。没有局编号的旧消息不能由服务端凭空证明其“产生于当前局”。
- 复杂状态/投射物/Host权限/PVE消息未完成同等级审查，初期关闭；**不宣称原客户端所有招式都可用**。未知消息不广播、不登记为支持。小型未知TCP消息计入有限预算后拒绝，超限或高危格式直接断开当前连接。
- 暂不开放任务、称号、修炼领奖和其他未审计奖励入口。客户端胜负/HP/击杀/共识只用于本局结束展示；旧数据库已有任务奖励规则也不能触发永久进度、金币、经验、排名或物品。
- 无一致结果、加载超时、参战者离开采用安全中止，不猜测赢家、不发奖。允许本局作弊风险仍然存在：验证来源/阶段不是完整服务端权威战斗。
- 公开人物预览只给现有公开展示字段；私有背包、邮箱和认证信息不得按任意UID查询。

### 交易重试与结果核对

价格、余额、物品归属与数量由服务端规则决定；扣款、授予、业务收据及资产审计在同一SQLite事务内提交。恢复后使用原有业务收据，不补做半笔交易。

原生购买帧没有客户端幂等键：**每个新的有效帧是新的购买意图**。密文重放会拒绝，但跨重连发送新帧不是自动重试。响应丢失时参考客户端不重发消费帧；先重新登录，调用 `receipts(session,after?)` 查看本人的有限分页资产变更，再核对余额与库存。返回最多50条审计记录及递增id，不返回其他账号内容或原始包体。此接口不是“跨连接恰好一次”保证。

### 资源与错误语义

`public_policy.py` 为默认政策，`public-policy.example.json`可显式覆盖有限数值；未知配置项拒绝。未认证每IP8、每监听预算全局64；游戏+SDK共享一组，认证TLS为独立有界组，不占在线玩家额度。TLS前取得租约；握手5秒、首头2秒、准入10秒；已认证空闲30秒；未完成原生半包也有独立期限，心跳不能无限延长准入。哈希2执行+8等待，排队最多2秒；不降低scrypt强度。

单客户端业务队列2 MiB，应用入站与待发送预算各64 MiB；编码/发送均有界。内核套接字缓冲、TLS缓冲、UDP发送缓冲属于额外但有界的资源，不等于Python业务队列预算。慢接收者超限关闭自己的连接，不能阻塞其他房间。UDP每授权200包/秒并校验字节/目标数；未知来源与已绑定端点预过滤预算分离。来源IP只用于限流，不是认证凭据，共享NAT账号的业务额度独立。

稳定错误包括 `invitation_required`、`invitation_invalid`、`invalid_credentials`、`invalid_session`、`invalid_ticket`、`account_already_online`、`rate_limited`、`server_busy`。客户端对繁忙采用有限指数退避，不自动重发经济操作。没有可靠失败帧的危险业务直接断开；不得伪造成功。

日志每10秒汇总、10 MiB轮转并保留5份，不记录认证/聊天/背包正文。指标只有固定事件类别，不把任意UID/IP/消息号作为标签。健康/指标只绑定127.0.0.1，不提供公网管理动作。服务就绪仅报告配置/监听成功，不输出“已获安全认证”。

### 独立客户端与离线管理

`python -m server.kk_local.public_client register --host HOST --port 17999 --server-name TLS_NAME --account NAME [--ca CA_PEM]`：交互隐藏输入密码和邀请码。将register换成login可验证TLS认证、身份初始化、大厅与UDP绑定，无DLL/VM依赖。示例客户端不自动重试购买，不是完整图形游戏。

`python -m server.kk_local.public_admin --database DB init` 只创建新库；旧库执行 `migrate --backup NEW_BACKUP`，先用SQLite backup API备份再显式迁移。维护工具必须与服务错峰，使用同一个进程级DB锁，不修改活跃账号库。其他命令：`invite --count N`（1–100）、`revoke-invite`、`disable --uid UID`、`set-password --account NAME`、`backup --output NEW_BACKUP`、`restore --source BACKUP`（目标必须新路径）。邀请码仅一次输出给管理员，数据库存摘要；不要将邀请码输出重定向到公开日志。

备份不得只复制主SQLite文件；需要包含WAL的一致性视图。恢复到新文件后执行完整性与余额/物品对账，再由管理员选择切换。工具不会覆盖原库。运行时管理员变更只通过服务内部受控事务或停服维护；不支持外部直接改表后仍要求内存授权缓存立即同步。

## 1. 无客户端测试

安装 `requirements.txt` 后运行 README 的单元测试。测试使用临时 SQLite 和回环随机端口；不需要生产数据库、VM、专有资源或已保存账号。

## 2. 真实客户端模式

Windows 上，使用自己合法持有、已适配到本地服务的客户端副本：

```powershell
python -m server.kk_local.sdo_service --client-root C:\MyGameLab\Client --runtime C:\MyGameLab\Run-001 --database C:\MyGameLab\accounts.sqlite3
```

`runtime` 每次必须是新目录。默认端口为本地账号 API 17999、登录 18000、游戏 TCP/UDP 18001、SDK HTTP 18082。路径可改，但适配模块与启动脚本中的路径/端口也必须相应配置。

这个命令只启动服务，不会自动复制或修改客户端，不会自动完成 GPK、SDK 启动与角色表初始化。缺少客户端配置、可用兼容模块、资源或就绪信息时可能无法进入游戏。不要通过伪造就绪文件绕过检查。

`sdo_service` 使用客户端根下配置解析地图，只在支持的模式/地图范围内准入。提供服务代码并不等于任意版本客户端即插即用。

真实配置加载依赖随本仓库发布的`tools/resource-recovery/spf2_index.py`、`spf2_extract.py`。这两项不是pip依赖，部署时必须保留相对路径。无mock的合成包测试位于`server/tests/test_client_config_package.py`；资源包由测试临时生成，不发布原客户端资源。

## 3. 账号

数据库通过 `Store` 自动建表，不随仓库提供预置真实账号。注册与登录在 `auth_service.py` 的 `kk-local-auth-v1` 本地 API；`tests/test_auth.py` 展示合成请求。API 消息为4字节网络序长度加 UTF-8 JSON，含 `schema/operation/arguments`。

典型顺序：register → login → regions → select_region → bind_client。正常路径还需要 Windows TCP/UDP 进程归属校验；不要发送测试固定回复代替密码认证。

若需为已有本地账号设置密码，使用 `python -m server.kk_local.accounts --database <路径> set-password <账号>`，在终端隐藏输入；不要将密码写在命令行。

## 4. 存储与业务

`accounts` 保存360字节档案，`inventory` 保存68字节物品记录；余额、商品目录、成交收据及训练状态分别持久化。完整原始记录保留未知字段。复制活动数据库应使用 SQLite backup，而不是单独复制主文件遗漏 WAL。

商城必须先导入有来源的完整记录并显式启用支持的商品类型。未启用或未实现分支不得扣款、授予物品或假报成功。所有奖励/经济政策均应单独审查。

`rooms.py` 的共享协调器是实验性本地多账号功能；原 SDK 认证服务仍限制每区单活动客户端。跨机器服务不能沿用本机 PID 验证，必须另行设计认证、TLS、授权及状态同步。

## 5. 协议扩展方法

1. 从原客户端实际请求确认方向、连接阶段、ID 和长度。
2. 检查消费函数，确认读取字段、类型、尾部与副作用，不只看消息号相近。
3. 在 `layouts.py/menu_layouts.py` 写严格解析，保留未明字段。
4. 在服务层校验当前账号、阶段、归属、容量、幂等和失败路径。
5. 先用合成夹具测试，再在授权隔离客户端验证实际显示/状态变化。
6. 区分结构恢复、本地服务设计和原客户端验证，不用一个测试通过覆盖整个协议族。

本包不携带原始研究证据。源码中的地址、ID和参考名称仅用于追踪兼容来源，不代表恢复了旧服务器源码。
