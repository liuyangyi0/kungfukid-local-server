# 客户端兼容方法与移植步骤

## 提供什么、不提供什么

本目录发布自行编写的兼容模块源码和原实验启动模板，不发布原版或修改后的 EXE/DLL、游戏素材、SDK、注入器、内存转储或现成虚拟机。启动模板不是通用安装器，其旧实验路径与模块文件名需要逐一适配。

此方法仅用于有权使用的本地客户端，让它访问自建服务；不连接旧公网，不规避第三方在线服务器的认证，不安装旧反外挂驱动。

## 模块职责

| 源码 | 作用 | 必须核对 |
|---|---|---|
| `kk_sdo_request_adapter.cpp` | SDK认证请求重定向到回环HTTP，使用本轮自建公钥 | SDK模块/导入、对象布局、地址偏移、公钥文件、端口 |
| `kk_sdo_input_provider.cpp` | 在原密码控件上使用已验证的用户态输入路径，保留遮罩 | 控件类型、虚表、事件槽、UI线程；不读取或记录密码 |
| `kk_sdo_http_path_probe.cpp` | 仅观察接口路径，辅助诊断缺失接口 | 不得扩大成记录查询串或认证正文 |
| `kk_roleprop_observer.cpp` | 观察角色配置表是否完成初始化并写就绪收据 | 当前模块基址、表位置、就绪文件与本轮客户端身份 |

这些源码存在版本绑定地址及 `C:\KK-Lab\...` 白名单。不能把白名单删除后用于任意程序，也不能把某个版本的地址照搬到另一版本。运行时模块/PID/创建时间的拒绝检查应保留。

## 构建

安装 Visual Studio C++ 工具及 Windows SDK，在 **x86 Native Tools Command Prompt** 中打开发布仓库根目录：

```bat
client-adapter\build.cmd
```

构建输出仅在本地 `build\adapter`，不会加入 Git。编译成功只证明源码可构建，不证明当前用户客户端版本兼容。

原 guest 模板期待以下名字：request-adapter.dll、input-provider-a07.dll、http-path-a07.dll、observer.dll。build.cmd使用这些名字。模板还依赖未提供的本地加载工具及已经可启动的客户端副本，所以不能把脚本复制过去就当完成部署。

## 集成顺序

1. 创建隔离 VM / 客户端副本；保留原安装文件，不原地修改。只启用所需的本机回环网络。
2. 根据自己的 SDK 和客户端版本确认上述源码的地址、导入、事件槽和数据布局；未知项停止适配，不猜地址。
3. 配置客户端正常启动所需的离线环境。原更新器、GPK 和旧驱动不包含在此包；这部分未满足时，仅创建服务仍不足以启动游戏。
4. 启动 `sdo_service`，读取本轮 `ready.json` 及公开的 `public-key.bin`；私钥只在服务内存，不放客户端。
5. 在启动的准确 SDK 进程中加载自己编译的请求与输入兼容模块；使用用户自行审查的加载方式。核对父子进程关系和创建时间，不按窗口名随便注入。
6. 等待请求适配和输入事件路径的 Ready 结果，然后让密码认证实际通过本地服务。不要直接发送“登录成功”绕过认证。
7. 观察原角色表就绪后才下发完整档案/装备；表未建时提前发包会导致客户端崩溃。
8. 客户端完成大厅交接后，若原登录层仍显示，需依据当前进程与真实连接证据隐藏该层；不要在登录过程中销毁窗口或强写战斗状态。
9. 逐项验证进入房间、设置更新、换队、开始/退出及实际输入，再扩展其他功能。

## 原实验脚本

`reference-scripts/Start-SdoOriginalWindowHost.ps1` 通过 VMware guest operations启动客体脚本；主机凭据路径只是引用，不包含凭据文件。

`reference-scripts/Start-SdoOriginalWindowGuest.ps1` 验证网络/端口、启动指定副本、加载兼容模块并等待就绪。它包含原实验绝对路径与版本化名称，须改成自己的配置。Windows Session 0不能作为可见游戏桌面；客户端应在已登录用户的交互会话启动。

本包不包含测试账号自动登录工具，以免发布个人凭据或实验账号配置。接入自己的安全凭据存储时必须保证口令不进入参数、日志、仓库或抓包。

## 常见误区

- 修改IP不等于恢复协议：认证、目录、档案、房间和战斗都有状态与时序。
- 服务端运行不等于客户端可用：版本、资源、SDK和角色表仍是前置条件。
- 输入控件能输入不等于认证成功；大厅能显示也不等于战斗或结算完成。
- 不把 SDK 旧式加密或游戏帧混淆当作公网安全方案。
